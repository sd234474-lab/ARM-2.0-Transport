| CP/ORG-форма | Пять вкладок; наименования/реквизиты и официальные контакты сгруппированы. Банковский контракт/форматы не менялись |

| Представители | Таблица имени/должности/телефона/email, заметное создание, выбор подписанта, одно редактируемое `name`; основание полномочий, статус, `user_id` сохранены |

`last_name/first_name/middle_name` скрыты только в новой форме. GET → draft → PUT
сохраняет старые значения, включая ненулевые. Сокращение имени не записывается:
«Иванов Иван Иванович» → «Иванов И.И.», «Эдуард» остаётся исходным; сложное имя
показывается целиком. Юридические реквизиты самого ИП с представителями не смешиваются.

Сохранены существующие SAVE/ID/VERSION/HIST/ACCESS, UI-A1, REP API и FK 0061.
Изменение состава колонок или компоновки не сопровождалось миграциями.
История по-прежнему загружается только по нажатию. Enter в read-only таблице техники
не сохраняет черновик CP/ORG — это отдельно проверено.

## Read API и совместимость

Добавлены только GET:

| Endpoint | Параметры |
|---|---|
| `/api/arm2/vehicles/search` | `q`, `type_id`, `owner_kind=CP/ORG/NONE`, `owner_id`, `state`, `sort`, `direction`, `limit`, `offset` |
| `/api/arm2/counterparties/search` | `q`, `status`, `legal_form`, `sort`, `direction`, `limit`, `offset` |
| `/api/arm2/organizations/search` | То же, с правом ORG VIEW |
| `/api/arm2/types/search` | `q`, `limit`, `offset`; используется typeahead, не заменяет принятый список TYPE |

Ответ: `{items, total, matched, limit, offset}`. `total` — весь доступный каталог,
`matched` — вся отфильтрованная выборка, не длина текущей страницы. `limit` 1–100,
`offset` неотрицательный; параметры сортировки, состояния и owner-сочетания проверены.
Сортировка имеет стабильный дополнительный ключ ID. `%` и `_` в запросе ищутся
буквально, NUL отклоняется с 422. Русский регистр учитывается независимо от нативной
локали PostgreSQL C; данные при поиске не переписываются.

Госномер для поиска допускает группирующие пробелы отображения и однозначные
латинские двойники. Существующий write-нормализатор VEH.F03 не менялся; это не
добавление правил табличного или анкетного импорта.

Прежние GET list по `/types`, `/vehicles`, `/counterparties`, `/organizations`
сохранены с прежним массивом и параметрами. Прежние POST/PUT/History не изменены.
Новый read-код расположен в `backend/app/arm2/read_routes.py` и подключён перед
динамическими маршрутами `/{id}`.

VIEW проверяется сервером. Имя TYPE/CP/ORG не раскрывается через VEH, если нет
права на соответствующий справочник; текущие связи сохраняются. Фильтрация по
закрытому справочнику не обходит это ограничение. Для сортировки по объединённому
владельцу необходим просмотр обоих справочников владельцев.

## Изоляция проверки

Все действия выполнялись в новой рабочей копии и её `.local/b1`:

- собственные venv/dev-зависимости, кеши и заново загруженные проверенные vendor binaries;
- отдельный PostgreSQL 17.11/PostGIS 3.6.2, порт **55447**, собственный `pgdata`;
- новая disposable `arm2_b1_test` и отдельная `arm2_b1_visual`, миграции только до 0061;
- API **18103**, frontend B1 **18102**, исходный frontend #42 **18104** — всё literal loopback;
- случайные собственные секреты; конфиг защищён ACL, `.local/` исключён из Git;
- собственный wrapper: reviewed allowlist плюс четыре точных GET search, без новых write-маршрутов;
- до тестов проверяются DSN и реальный `data_directory`; Python egress на прежние порты запрещён;
- отрицательная проверка защитного запуска отвергает старые DSN до попытки подключения;
- stop проверяет PID/creation time/команду/PGDATA, не использует массовую остановку по имени или порту.

Установленный ARM2-UAT, ARM1, их runtime/БД/секреты и серверная «Метка» не
использовались. Существующие deployment-пакеты в `deploy/` оставлены без изменений;
новая адресная политика относится только к тестовому B1 wrapper.
Не выполнялась новая широкая инвентаризация Windows или чтение пользовательских БД.

Начальные синтетические fixtures: 130 VEH, 110 CP, 105 ORG, несколько TYPE и
представители с ненулевыми legacy частями ФИО. Они созданы существующими сервисами
ARM2 с реальными ID/версиями/историей. Браузерные сценарии добавляли собственные
тестовые записи. Ни старые данные, ни повторный пользовательский импорт не применялись.

## Воспроизведение на отдельном Windows-стенде

Только новая рабочая копия; подготовка не предназначена для установленного UAT.
Нужны уже доступные системные Python/Node/Edge. Скрипт runtime скачивает отдельные
официальные PostgreSQL/PostGIS ZIP и проверяет SHA256. Системные службы, PATH,
firewall, registry и пользовательские ярлыки не изменяются.

```powershell
# В новой копии ветки, свободные 55447 / 18102 / 18103 / 18104.
python -B ops/arm2_b1_prepare.py dependencies
python -B ops/arm2_b1_prepare.py runtime
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py init
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py seed
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py tests
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py start
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py baseline
node ops/arm2_b1_browser.cjs
# Полный scoped stop/start, затем чтение ранее сохранённого:
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py stop
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py start
node ops/arm2_b1_browser.cjs --reopen
& .local/b1/python/Scripts/python.exe -B -m unittest discover -s ops -p test_arm2_b1_boundary.py -v
& .local/b1/bootstrap/Scripts/python.exe -B ops/arm2_b1_check.py stop
```

Init/runtime отказываются перезаписывать существующий стенд. Пароль `b1-admin`
случайный, только в собственном `.local/b1/sandbox.json`; его нельзя публиковать.
Браузерные сценарии сохраняют новые синтетические записи. Исходный frontend #42
для снимков извлекается из Git в свою папку; пользовательские программы не копируются.

## Сознательно отложено

B2 — ручная привязка/переназначение VEH из CP/ORG; B3 — документы, реальные СТС,
тарировка и подтверждения. Нет псевдоготовности/колонки «Контроль», нового импорта,
анкетного обмена, договоров или расчётов. Lookup показывает ограниченную выдачу
совпадений; уточнение запроса ищет по всему каталогу. Физическая миграция старых
частей ФИО и совместимость прежних печатных форм не подменяются их удалением.

Блокеров предметной модели для разрешённого B1 не осталось. Требуется последующая
операторская приёмка и независимая проверка PR. Merge, deployment и обновление
установленного экземпляра не выполнялись.
