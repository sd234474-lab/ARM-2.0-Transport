## Операторский маршрут

В «Технике» доступны «Выгрузить в Excel» и, при штатном праве редактирования, «Загрузить таблицу». Экспорт использует **всю отфильтрованную выборку**, серверную пагинацию и согласованный снимок REPEATABLE READ. Браузерная страница списка не ограничивает выгрузку. Недоступные TYPE/owner-поля отсутствуют, ID и значения записаны текстом с форматом Excel `@`.

1. Выбрать XLSX/CSV/TSV либо вставить TSV из Excel. У многолистового XLSX отдельно выбрать один лист; до выбора рабочий набор не создаётся.
2. Над колонками проверить «Укажите реквизит» / «Не загружать». Неизвестные заголовки не назначаются автоматически. Можно исправлять ячейки, исключать/возвращать строки, массово задавать значение выделенным строкам. Изменения и решения последовательно сохраняются на сервере; состояние подтверждения видно в интерфейсе.
3. Проверить CREATE/UPDATE/SKIP/CONFLICT, совпавшую VEH, строки-источники, ошибки, варианты дубликатов, исходное/текущее/загруженное значения. «Принять проверенные поля» выбирает только непротиворечивые допустимые поля; спорные варианты выбираются отдельно. Выбор полей ещё не пишет VEH.
4. Отдельно подтвердить замену занятого владельца или госномера. «Сохранить выбранные изменения» применяет по одной VEH с повторной серверной проверкой. Ошибочный независимый реквизит можно оставить непринятым, сохранив остальные допустимые поля.
5. После частичного сохранения увидеть **фактические** результаты и открыть штатное событие HIST. При потере связи проверить серверные результаты перед продолжением. Закрытый браузер и перезапуск API не удаляют набор; открыть его может только автор после штатной аутентификации.
6. Скачать отказы в Excel, затем завершить или отменить набор. Если данные/результаты изменились после скачивания, сервер требует новый отчёт. Завершение удаляет временную таблицу; принятые VEH/HIST и краткий постоянный протокол остаются. Отмена после SAVE не является откатом.

Пустая ячейка ничего не очищает. Отдельный CLEAR доступен только для TYPE, владельца CP/ORG, Wialon ID и nullable model. CLEAR владельца снимает обе ссылки, не удаляя CP/ORG. При исходном NULL подписанного снимка явный CLEAR всё равно является самостоятельным намерением и не теряется при трёхстороннем сравнении.

## Этап TYPE

- Nullable `plate_category`: «Автомобильный» / «Самоходная техника», без вывода из имени. Полнота требует имени, категории, STS=True и явных ответов по тарировке/Wialon. False для двух последних признаков — заполненный ответ.
- STS новых/редактируемых TYPE строго True. Исторический NULL не подменяется автоматически: карточка показывает незаполненность и требует явного выбора «Требуется». Ответ чтения сохраняет исторический NULL.
- Новое назначение REVIEW запрещено; историческая связь с REVIEW сохраняется. Без TYPE номер проверяется по любому из двух утверждённых форматов. Новая/изменённая связка TYPE–номер проверяется по категории; смена категории используемого TYPE не проходит при несовместимых VEH. Блокировка TYPE сериализует смену категории и назначение VEH.
- Список TYPE ищет и фильтрует REVIEW/CONFIRMED по всему серверному каталогу с пагинацией. Категория показана в колонке/карточке; история загружается по действию пользователя.

Миграция **0065 (после 0064)** добавляет nullable категорию; прежние CONFIRMED становятся REVIEW с реальным системным событием HIST и увеличением VERSION. Уже REVIEW, исторические STS NULL, TYPE-ID, VEH-ID и связи не переписываются. Downgrade отказывает при данных/истории категории, включая историю после её очистки; никаких автоматических удалений/repair.

## SAVE, восстановление и права

`bulk_diff.py` только сверяет данные. Запись проходит через существующие `create_object` / `update_object(partial=True)` с `SaveContext(source="arm2-table", correlation_id=command_id)`. Тело `object_save.py` и `history_store.py` не менялось. CREATE использует штатный ID.R01, обязательный уникальный нормализованный номер, default name=номер и состояние «Действующая». Пробелы номера удаляются только на входе B4; ручной канал не расширен.

VEH-ID при наличии первичен, номер сверяется; разные объекты по ID и номеру дают блокирующий конфликт строки. TYPE/CP/ORG сопоставляются по существующим ID/точным однозначным именам, без создания справочников по тексту и без code. Дубликат, равный текущему ARM, остаётся альтернативой при наличии другой противоречащей строки. Похожие номера — только ограниченная подсказка, без автоматического объединения.

**Одна HTTP-команда — одна VEH — одна внешняя SQL-транзакция:** предметная запись, VERSION, HIST и `arm2_bulk_receipts` фиксируются совместно. Устойчивый UUID команды и fingerprint запрещают повтор с другим содержимым. Идентичный повтор возвращает проверенный сохранённый результат; повторный CREATE/HIST не выполняется. Проверка результата сверяет receipt, действительный VEH, HIST-ID, correlation, автора, источник и версии. UNKNOWN блокирует запись, завершение и очистку до достоверной проверки; интерфейс не превращает неизвестное в успех. Заведомо незафиксированная попытка остаётся временным отказом и требует нового сравнения/явного решения.

Миграция **0066 (после 0065)** добавляет:

| Таблица | Срок жизни / назначение |
| --- | --- |
| `arm2_bulk_sessions` | Личный серверный набор, mapping, edits, CLEAR, approvals, preview и временные отказы; нет таймера удаления |
| `arm2_bulk_receipts` | Постоянный краткий протокол: операция/команда, автор, время, источник/лист, VEH, поля, версия, FK на HIST; без исходного файла и подробных отказов |
| `arm2_bulk_cleanup` | Аудит явной административной очистки; не предоставляет доступ к чужому содержимому/продолжению |

У receipt нет каскадной зависимости от временной сессии. Downgrade 0066 отказывает при наличии любого рабочего набора, протокола или аудита. Пустой round-trip сохраняет существующие VEH/HIST и последовательности. Старые B3 migration-тесты сохраняют исторические переходы и loss guards; legacy-фикстура 0064 подготовлена в её замороженном SQL-представлении, а не новыми TYPE-командами для другой схемы.

Все операции повторяют штатные VEH VIEW/EDIT и ограничения текущей базы/организации. Назначение/снятие владельца проверяет VIEW+EDIT прежнего и нового CP/ORG; TYPE требует VIEW и предметной допустимости. Смена прав после preview не обходит SAVE. Только реальная роль ADMIN_OPERATOR может выполнить отдельную очистку; даже администратор не продолжает чужую загрузку. Новые permissions/роли не добавлены. Просмотр минимального протокола и переход в HIST также проходят серверную авторизацию.

Исторические ненормализованные соседние поля не переписываются побочно общей нормализацией: если общий адаптер изменил бы непринятое поле, вся данная VEH откатывается с понятным требованием сначала явно исправить карточку.

## Подписанный XLSX и конфигурация

Перед использованием экспорта администратор задаёт **`ARM2_TABLE_SIGNING_KEY`** в штатной серверной конфигурации окружения: криптографически случайное стабильное значение не менее 32 символов, например результат `secrets.token_urlsafe(48)`. Не включать значение в Git, XLSX, журналы или frontend. В коде нет рабочего/default секрета; при отсутствии корректного ключа экспорт отвечает 503. Внешний импорт не требует ключа.

Служебный veryHidden-лист содержит канонический JSON, исходные разрешённые значения, VEH-ID/версию, область базы и HMAC-SHA256. Скрытость листа не считается защитой. Подпись проверяется сервером; повреждение, другой tenant/ключ или недостоверный манифест переводят таблицу во внешний режим с предупреждением. Строки без подтверждённого снимка явно показаны как внешние. Версия, введённая в CSV/Excel, не становится expected_version. Ротация ключа делает старые манифесты внешними; автоперезаписи нет. Полный исходный XLSX постоянно не хранится.

| Ограничение | Значение |
| --- | --- |
| Тело запроса / файл | 5 МиБ, фактически прочитанные байты, включая запрос без Content-Length |
| Импорт | 1000 строк данных, 32 колонки, 1000 символов/ячейку; изменяемый текст VEH ≤500 |
| XLSX ZIP | ≤200 членов, ≤20 МиБ суммарно распакованных, ≤10 МиБ на член; только STORE/DEFLATE |
| Разбор | Отдельный завершаемый subprocess, 8 секунд, не более 2 одновременно на API-процесс; event loop не блокируется |
| Содержимое | Формулы/ошибки Excel, макросы, внешние ссылки, DTD/entities и NUL отклоняются; формулы не вычисляются |
| Текст | UTF-8/BOM, CSV с comma/semicolon/tab, TSV; fallback CP1251; выходной Excel — текстовые клетки |
| Экспорт | До 10000 совпавших VEH целиком; выше — 413 с просьбой сузить фильтр, без частичного файла |
| Подсказки похожих | До 200 кандидатов по префиксу, до 3 подсказок; не исчерпывающий поиск и не объединение |
