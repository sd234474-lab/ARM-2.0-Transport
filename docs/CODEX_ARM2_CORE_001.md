## Цель и строгая граница

Реализовать один **внутренний**, переиспользуемый путь работы с зарегистрированными типами объектов:
`описание типа → проверка команды → предметные правила → контроль версии/изменений → сохранение предметной записи + обязательное событие общей истории в одной транзакции`.

В этом пакете **ввести контракт и подключить к нему только TYPE**. Проверить повторное использование на **втором искусственном тестовом типе с тестовой таблицей/адаптером**, не объявляя готовность реального VEH. Не открывать public HTTP/CRUD, UI, read-history API, auth/permissions, реальные права и массовый импорт. Предметные правила TYPE не менять.

### Обязательные свойства контракта

1. **Регистрация:** явно описанные `object_type`, ID prefix, разрешённые поля и их типы/nullability, поля истории и их безопасное отображение, допустимые действия, предметный адаптер/валидатор. Ни ORM `__dict__`, ни произвольная сериализация JSON/details/request body. Неизвестный тип, поле, действие, вложенная коллекция или секрет — отказ до записи. TYPE: `name`, `requires_sts`, `requires_calibration`, `requires_wialon`, `status`, `version` для истории. Внешние клиенты не могут менять `status`, `version` или `id` как обычные входные поля. Отличать пропуск поля от явного null; `False` остаётся `False`.
2. **Создание TYPE:** нормализовать наименование и признаки существующими `vehicle_type_rules.py`, вычислить REVIEW/CONFIRMED прежним алгоритмом, выдать ID через `ids.next_id(db,'TYPE')`, создать версию 1 и событие CREATED со всеми безопасно разрешёнными полями. Не добавлять вторую последовательность. Сохранять TYPE + событие в **одной переданной Session**; общий слой не вызывает самостоятельный `commit`.
3. **Обновление TYPE:** с реальным `expected_version`, `SELECT FOR UPDATE`/эквивалентной гонкобезопасной защитой; нормализация, предметная уникальность имени и БД-ограничения сохраняются. На no-op не повышать версию и не писать фиктивную историю; при реальном изменении повысить версию и записать только изменённые разрешённые значения, включая изменение `version`. При ошибке событие и предметное изменение не должны оказаться сохранёнными раздельно.
4. **Автор и источник:** служебный контекст вызывающего доверенного server-side кода (actor_kind, actor_id, source, необязательный correlation_id) передаётся в общую операцию. Проверить непустые значения; **не выдавать этот внутренний контракт за существующую аутентификацию** и не принимать `actor_id` из клиентского payload как достоверное лицо. Нет реального auth-контекста → публичную запись не открывать. Не выдумывать оператора.
5. **История:** повторно использовать `HistoryEvent` и `append_history_event`, не создавать другой журнал. TYPE whitelist переносится из захардкоженного `history_store.py` в описание TYPE с жёсткой безопасной проверкой. Не допускать произвольных типов: нынешние PostgreSQL CHECK для TYPE/VEH остаются ограничениями первого среза; **расширение на новую реальную сущность требует отдельного согласованного шага миграции, без снятия DB CHECK сейчас**. Для тестового второго объекта проверять общий контракт/алгоритм через изолированный тестовый адаптер без регистрации в настоящей production таблице истории (не подделывать успех на реальном VEH).
6. **Безопасность доступа к низкоуровневому сохранению:** существующие `create_vehicle_type`/`update_vehicle_type` сейчас являются внутренними операциями без обязательной истории. После изменения ни один новый путь приложения не должен применять их напрямую, обходя общее сохранение. Решить доступность legacy низкоуровневых функций явным разделением internal-only/защищённых адаптеров; **доказать тестами отсутствие обхода на поддерживаемом service/API пути**, не утверждать невозможность DBA/raw SQL обхода. Старые unit/integration tests переподключить по существу, не оставить прежние тесты как ложное доказательство полного поведения.
7. **Транзакция:** весь процесс одной команды выполняется под одной управляемой вызывающим кодом транзакцией; add/flush без внутреннего commit; rollback отменяет и TYPE, и HISTORY. Для batch/асинхронности/внешних побочных эффектов транзакционные гарантии отдельно открыты и не обещаются в этом пакете.

## Независимо проверяемая приёмка

- TYPE create: ID `TYPE-000001`, version 1, правильный статус и строго разрешённый CREATED diff, реальные actor/source. Одно действие — одно событие.
- TYPE update: `null → false` и изменение статуса, version 1→2, все изменения в одном UPDATED событии; no-op даёт ни версии, ни события.
- Конкурентное изменение одной версии: ровно один победитель, другой конфликтует; не создаёт ложного события.
- Некорректные поля, секреты, вложенные объекты, неправильный тип ID, недостоверный/пустой технический контекст отклоняются.
- Поддерживаемый общий save path не способен сохранить TYPE без истории; искусственно вызвать ошибку добавления истории и убедиться, что транзакция предметной записи не подтверждена.
- В тестовом втором объекте новый набор полей и независимая предметная проверка подключаются через тот же общий save-контракт, без копирования кода версий/diff и без отдельного журнала. Если тест без реального DB-event, это указывается как граница доказательства.
- Отсутствие API/UI/прод-миграций; существующие проверки TYPE не ослаблены.
- По существующим тестам исправлено устаревшее ожидание поддержки TYPE ID без изменения правила ID.
- `pytest` только на **заведомо disposable PostgreSQL с суффиксом `_test`**; показать точную команду, pass/fail, удаление тестовой DB. Если нет disposable DB — не мигрировать чужую БД, отметить тесты как NOT RUN.
- `ruff check` изменённых файлов, `git diff --check`; отдельно указать статус CI. В baseline прежний Ruff issue `backend/alembic/versions/0055_image_limits.py` не исправлять этим пакетом.
