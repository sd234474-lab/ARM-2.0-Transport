## Что подтверждено
- В новой основе **отсутствуют** файлы старого ARM: `contractor_models.py`, `contractor.py`, `contractor_import.py`, `Contractor.tsx`.
- В основе есть инфраструктура маршрутов, аутентификации, БД и интерфейса.
- В старом ARM 1.0 существовали специфические договорные, территориальные, технологические механизмы; **не переносить их в первую версию ARM 2.0**.
- Допущение владельца, что территории и виды работ Transport MAX не менялись существенно, **пока не подтверждено сравниванием поведения**; не затрагивать их без прямой необходимости.

## Обязательные границы безопасности установки
- Работающая ARM 1.0 и новая ARM 2.0 должны иметь отдельные параметры запуска, базы данных, тома/каталоги, порты, логи и конфигурацию; это пока **цель**, не проверенный факт.
- Нельзя запускать два приёмника для **одного и того же MAX-бота**. Не включать в новую тестовую установку `receiver`, `worker`, `publisher`, `trainer` и другие фоновые сервисы без отдельной оценки побочных эффектов. Новый модуль справочников не требует их в первом тесте.
- `compose.yaml` нельзя просто запустить второй раз с прежними именами/томами/паролями и считать установки независимыми.
- Реальные параметры компьютера, порты и текущая конфигурация неизвестны; Codex должен предъявить отдельный план безопасной установки до любых изменений рабочих служб.
- Хранить новые исходники отдельно в целевом репозитории; никакой записи в старый `sd234474-lab/max_bot_foto`.

## Строгий режим для Codex
1. Открывать только перечисленные в **конкретном задании** файлы и точные диапазоны. Максимум один дополнительный файл при объяснённой зависимости; если нужно больше — блокер и остановка.
2. Не выполнять `find .`, `rg` по всему репозиторию, `cat` крупных модулей, полный обзор всех миграций и тестов без адресного разрешения.
3. Один запуск — одна ограниченная задача с собственным доказательством результата. Не переходить к следующей автоматически.
4. Не читать всю Google-таблицу заново: применять только ID требований, выданные на текущий пакет.
5. Не изменять `compose.yaml`, `.env`, базу, права, территориальные справочники, виды работ, договоры и сторонние модули без отдельного задания.
6. Если реальное состояние кода расходится с этой картой — сообщить конкретный путь/расхождение и остановиться; не проводить самостоятельное широкое расследование.

## Приоритетные предметные принципы будущих пакетов
- `ID.R01`: один стабильный предметный ID для записи, префикс + шестизначная последовательность; не путать с бизнес-кодами/номерами. Префикс `VEH-` утверждён; остальные префиксы согласовать до реализации.
- `DISC-TYPE-04/05/06/07`: явные три признака типа, REVIEW/CONFIRMED автоматически; отдельные правила по СТС и Wialon смотреть в строках.
- `DISC-CP-46`: Контрагент создаётся по name, полнота определяется без обязательного ИНН.
- `HIST.R01`, `VER.R01`: единая история и защита редактирования от потери чужих изменений.
- Сохранение старого ARM 1.0 как контрольного образца; данные ARM 1.0 **не мигрируют** по новому решению владельца, пока оно не отражено в конфигурации.
